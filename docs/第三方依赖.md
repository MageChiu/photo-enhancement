# 第三方依赖与发布前审计

本清单是工程追踪，不构成法律意见。使用系统/Homebrew 库只是开发便利，不免除应用分发时的许可证义务。

| 依赖 | 用途 | 许可证/注意项 |
| --- | --- | --- |
| LibRaw 0.22.2（仓库源码） | RAW | 上游提供 LGPL-2.1 / CDDL 双重许可；必须明确选择与遵循一种。构建没有启用额外 demosaic packs、DNG SDK 或 RawSpeed |
| libjpeg-turbo | JPEG、LibRaw 有损 DNG | 需随分发包含上游 IJG/BSD/zlib 等许可与声明 |

| libtiff | TIFF / BigTIFF 照片输入 | libtiff 宽松许可，分发需保留上游版权和声明；移动固定 4.7.2 |
| Little CMS 2 | ICC | MIT |
| FreeType | 字体栅格化 | 可选择 FreeType License；字体文件有自己的独立许可，应用不打包系统字体 |

## 移动端源码锁定

cmake/PortableDependencies.cmake 固定源码 URL 和 SHA256：libjpeg-turbo 3.1.1、libpng 1.6.47、libtiff 4.7.2、zlib 1.3.1、Little CMS 2.17、FreeType 2.13.3、libwebp 1.5.0、libheif 1.19.7、libde265 1.0.16。LibRaw 继续由 Git 子模块固定为 0.22.2。

移动端依赖静态链接入内核；iOS 再合并为设备和模拟器静态库。构建产物和下载文件位于忽略目录，不作为额外嵌套仓库提交。最终分发需针对这些实际链接方式准备许可声明、源代码及必要的重链接材料；本轮未生成商店发布包。macOS Homebrew 构建的实际依赖版本不同，不能用这份移动端锁定清单替代 macOS 二进制依赖清单。

## 为什么没有使用 Exiv2

原方案计划使用 Exiv2。其 GPL 许可会影响应用整体分发策略，因此首版没有在尚未确定产品许可证时默认集成。当前只读取必要的 EXIF TIFF 标签，并用白名单重建导出信息；它不是“完整原样保留 EXIF”的替代品。

如后续必须保留完整元数据，需要先确定应用许可证/合规方案，再评估 Exiv2 或其他方案。不要直接复制 MakerNote、旧缩略图、方向、图像尺寸或 GPS 到重绘后的图片。

## 上架/分发前门禁

1. 锁定每个依赖版本、源代码校验值、编译选项与平台 ABI。
2. 导出实际二进制依赖闭包和完整许可声明，不能只列直接依赖。
3. 为所选 LGPL 等许可准备相应的源码/重链接等履约材料。
4. 决定 HEIF 编码器及其许可/专利策略，必要时仅提供 JPEG/PNG 输出。
5. 单独审核字体、样张、预设及应用名称/图标的权利。
6. 完成 Apple 签名/公证、Android/HarmonyOS 签名与各自应用市场审查。
