# 功能迭代

更新：2026-10-21。滤镜配方单独维护在 [滤镜清单](滤镜清单.md)，架构背景见 [技术方案](技术方案-v1.md)，检查事实见 [验证记录](验证记录.md)。本页安排工作顺序，不将已编写代码等同于已经验证。

## 迭代方向

| 方向 | 当前基础 | 下一步 | 完成依据 |
| --- | --- | --- | --- |
| 解码与导出 | JPEG→JPEG/PNG/HEIF 分条编辑；HEIF 大图网格编码，计入压缩缓存预算；其他输入组合保留整图预算检查；RAW 预览半尺寸估算已调整 | P0：JPEG→HEIF 网格分块编码已接入，待用户重编译同一文件验证尺寸、色彩、元数据与相框；压缩图块缓存仍计入预算，超出预算保留拒绝 | 用户同一文件能够完成预期导出，或得到明确的限制及可选方案；不能通过提高上限、静默缩图或更换格式掩盖 |
| 滤镜能力 | LUT、自适应起点、材质、暗角、颗粒已接线 | P1：先验证共用管线，再集中调整寒峻；后续滤镜逐款迭代 | 强度 0、手动参数保持、预设往返、完整/条带导出，以及用户效果确认 |
| 边框与品牌 | 布局、EXIF 开关、品牌文字、PNG、独立边框预设已接线 | P1：处理真实反馈中的排版/字体/图标问题；之后再扩充模板 | 预览/导出内容一致、缺失 EXIF 不占位、图标和文字不裁断 |
| 编辑体验 | 原片点击/按住对比、历史、当前照片滤镜缩略图已接线 | P1：确认缩放位置、快速切图、异步预览和错误提示；P2 再扩展对比方式 | 原片对比不改变配方或导出，旧请求不覆盖新照片 |
| 平台与交付 | macOS 打包脚本、iOS/Android/鸿蒙源码构建入口已有 | P2：按用户实际工具链反馈修复各端整包构建，再处理相册、签名和分发 | 对应平台构建产物与实际反馈，不能用桌面通过替代移动端验证 |

## 当前顺序

1. 导出阻塞优先：先确认输入文件与目标格式，再修对应处理路径。区分输入解码、像素编辑、输出编码的峰值；JPEG 分条编辑与 HEIF 网格编码分别计算缓存和工作区，不用直接放宽预算代替处理能力。
2. 寒峻收敛：以用户参考为目标，单款效果先确认。通用纪实滤镜保留作对照。
3. 边框及编辑体验修复：以用户复测问题为准，避免同时扩张模板和交互。
4. 平台验证和分发按工具链条件安排，不阻塞桌面核心问题定位。

## 状态规则

- 计划：有目标及完成依据，尚未实现。
- 已接入 / 待验证：源码已连接，尚无本轮运行结果。
- 验证通过：记录命令、平台、版本及结果。
- 效果确认：用户对具体滤镜或体验确认。

每轮只推进明确范围；滤镜清单记录配方变化，功能迭代记录管线与交互任务，验证记录只记录实际发生的检查。本轮测试仍由用户执行。
