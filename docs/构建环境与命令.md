# 构建环境与命令

本轮「纪实光影」、原片对比与相框新增了 C++ 接口和 Dart 配方字段，需内核与应用一起重新构建并完整退出重启。由用户执行编译和测试：`sh scripts/build_macos.sh --verify --open`。只编译打包使用 `sh scripts/build_macos.sh --open`；开发运行使用 `sh scripts/dev_macos.sh`。移动端继续使用对应构建脚本，本轮没有执行移动端工具链验证。

所有命令在项目根目录执行。脚本默认只编译，不执行样张或人工验收，也不推送、上传或发布应用。macOS 的 `--verify` 是可选的自动化检查开关。

## 共用工具

- Git 与 Xcode Command Line Tools（完整 Xcode 安装后包含）。
- Python 3、CMake 3.20 或更新版本；Android 另外安装 SDK Manager 提供的 CMake 3.22.1。
- macOS、iOS、Android 使用 Flutter 3.47.7，版本固定在 app/.fvmrc；将对应 SDK 的 bin 加入 PATH。鸿蒙使用独立的 ohos Flutter SDK。
- 首次构建需要网络：Flutter 包、Gradle 和固定版本的图像依赖源码会下载到本地。图像依赖在 CMake 中校验 SHA256。

```sh
brew install cmake ninja pkgconf
git submodule update --init --recursive
flutter --version
flutter doctor -v
```

## macOS

安装完整 Xcode，首次打开完成组件安装；安装图像开发库：

```sh
brew install jpeg-turbo libpng little-cms2 freetype webp libheif
sh scripts/check_toolchains.sh macos
sh scripts/build_macos.sh
```

输出：dist/光屿.app、dist/光屿-macOS.zip。希望打包后立即启动时，使用 `sh scripts/build_macos.sh --open`。

高像素照片无需再配置 `PHOTO_CORE_MAX_PIXELS` 或 `PE_MAX_PIXELS`。JPEG 预览使用缩放解码，JPEG→JPEG/PNG/HEIF 原尺寸导出的编辑阶段采用分条处理；HEIF 大图使用 1024×1024 网格分块编码，RAW 和其他输入格式仍需整图解码，分别按设备内存预算检查。HEIF 编码需 libheif ≥1.19.7；已安装旧版可运行 `brew upgrade libheif` 后重新构建。渐进式 JPEG 的全尺寸系数缓冲也计入预算。详细资源策略见 README。

```sh
# 完整退出旧应用后，重新编译并开发运行：
sh scripts/dev_macos.sh
# 或重新生成可双击应用：
sh scripts/build_macos.sh --open
```

不需要手动移动图片或动态库。必须完整重启，热重载不会替换已加载的内核；旧 CMake 缓存中遗留的 PE_MAX_PIXELS 已不被当前源码使用。

## iOS

在 Xcode → Settings → Components 安装 iOS 平台和 Simulator runtime。本机曾报告缺少 iOS 26.5 平台组件；仅有 SDK 头文件仍可能无法生成应用目标。安装方式见 [Apple 平台组件说明](https://developer.apple.com/documentation/xcode/downloading-and-installing-additional-xcode-components)。

```sh
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
sh scripts/check_toolchains.sh ios

# 模拟器应用，无需开发者签名。
sh scripts/build_ios.sh --simulator

# 设备 Release 编译，不签名；产物不能直接安装真机。
sh scripts/build_ios.sh --device
```

脚本先交叉编译设备 arm64、模拟器 arm64/x86_64 的完整静态依赖闭包，再编译 Flutter 应用。原生库输出在 app/ios/PhotoCore，应用输出在 app/build/ios。

真机签名：在 Xcode 打开 app/ios/Runner.xcworkspace，进入 Runner → Signing & Capabilities 选择自己的 Team 和 Bundle Identifier，然后运行 `sh scripts/build_ios.sh --signed`。脚本不内置账号、证书或 Team ID。

只想构建图像内核时，运行 `sh scripts/build_ios_core.sh`。

## Android

安装 [Android Studio](https://developer.android.com/studio)，使用 JDK 17 或 Studio 自带 JBR。在 SDK Manager → SDK Tools 安装 Android SDK Command-line Tools (latest)、NDK (Side by side) 和 CMake；具体版本以本项目配置为准。参见 [Android 官方 NDK/CMake 安装说明](https://developer.android.com/studio/projects/install-ndk)。

Flutter 3.47.7 的本地 Gradle 配置要求 compile SDK 36、NDK 28.2.13676358；项目显式使用 CMake 3.22.1。

默认 SDK 路径示例；自定义安装时修改 ANDROID_HOME：

```sh
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$PATH"

sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.0.0" \
  "ndk;28.2.13676358" "cmake;3.22.1"
sdkmanager --licenses
flutter config --android-sdk "$ANDROID_HOME"
flutter doctor -v

sh scripts/check_toolchains.sh android
sh scripts/build_android.sh
```

输出目录：app/build/app/outputs/flutter-apk；默认 app-release.apk 包含 arm64-v8a 和 x86_64。Gradle 为每个 ABI 构建图像内核，不使用 macOS 动态库。

当前 Release 使用项目原有的开发签名，仅用于本地开发分发。应用市场构建前需要配置自己的 keystore 和签名。

## HarmonyOS / OpenHarmony

安装 [DevEco Studio](https://developer.huawei.com/consumer/cn/deveco-studio/)，并在其 SDK Manager 中安装对应的 HarmonyOS/OpenHarmony SDK，包括 native、ArkTS 和工具组件。保留 DevEco 配套的 Node、ohpm、hvigor、JDK；不要随意混用其他主版本。

另外获取 [OpenHarmony-SIG 的 ohos Flutter](https://gitee.com/openharmony-sig/flutter_flutter)，按该分支 README 选择匹配的 DevEco/SDK。Dart 至少需要 3.6。官方 Flutter 3.47.7 不能替代 ohos Flutter。

目前尚未在本机锁定并编译完整的 ohos 工具链组合；脚本提供源码接入入口，首次 HAP 编译可能暴露分支 API 或插件适配差异。

设置路径。以下 DevEco 路径是示例，以实际安装位置为准：

```sh
export TASK_DEVECO_CONTENTS="/Applications/DevEco-Studio.app/Contents"
export DEVECO_SDK_HOME="$TASK_DEVECO_CONTENTS/sdk"
export PATH="$TASK_DEVECO_CONTENTS/tools/ohpm/bin:$TASK_DEVECO_CONTENTS/tools/hvigor/bin:$TASK_DEVECO_CONTENTS/tools/node/bin:$PATH"

# 查找 native 工具链；输出通常位于某个 native/build/cmake 目录。
find "$DEVECO_SDK_HOME" -name ohos.toolchain.cmake

# 替换为实际路径。OHOS_SDK_NATIVE 指向 native，而不是它的父目录。
export OHOS_FLUTTER="/你的路径/ohos-flutter/bin/flutter"
export OHOS_SDK_NATIVE="/你的路径/native"

sh scripts/check_toolchains.sh ohos
sh scripts/build_ohos.sh --prepare-only
```

随后用 DevEco Studio 打开 app/ohos，选择 SDK、Bundle Name，并配置本机签名。首次生成的 EntryAbility 包含文件桥接，后续脚本不会覆盖自定义宿主代码。准备后执行：

```sh
sh scripts/build_ohos.sh
```

脚本编译 arm64-v8a 内核并放入 entry/libs，再调用 ohos Flutter 的 `build hap --release`。HAP 通常位于 app/ohos/entry/build/default/outputs/default；以该分支实际构建输出为准。

ohos SDK 的 `pub get` 可能重新解析 pubspec.lock；切回官方 Flutter 构建其他端前，应重新运行 `flutter pub get`。不要同时在同一 app 目录使用两套 Flutter SDK 构建。

## 当前范围

共享编辑器已包含十项基础调色、八色 HSL、五点 RGB 主曲线、分离色调、局部锐化/降噪、LUT、边框和预设。移动端导出通过系统文件选择器完成，未实现直接写入相册。移动端 HEIC 通过 libde265 解码，默认不包含 HEVC 编码器，导出使用 JPEG/PNG。

本机已做原生编译、Swift 类型与原生链接检查，以及必要的自动化回归；没有进行真实样张或设备验收。最后一轮完整重构建/重打包未执行，因此已有 dist 文件不保证包含最后的源码改动。请用上述脚本在安装好环境后重新生成。
