## 已知构建反馈与修复

1. LibRaw 常规实现与合并版源文件被同时编译，产生重复符号。CMake 已排除替代的合并版文件。
2. 原生测试的 JPEG 头文件之前缺少标准类型声明。已经调整头文件顺序。
3. 对 JPEG APP1 / APP2 元数据读取时机进行了修正，在解码器释放标记内存之前复制 EXIF / ICC。
4. 根据当前 Flutter SDK 的类型错误，调整卡片主题配置。用户随后反馈共享内核、命令行、测试程序均已编译，macOS Debug 应用已构建并启动。该反馈不包含原生或 Flutter 测试执行结果。
5. 用户后续反馈 Debug 构建成功，但 Flutter 提示前台激活失败。只读检查 SDK 后确认，该提示来自附加调试后系统打开应用的返回码，并不能单独证明应用崩溃。已在 macOS 宿主中增加启动后显示并激活主窗口的处理；该修改尚待重新构建验证，不声称已经根治所有启动问题。

其中 Debug 构建和启动已有用户反馈确认；其余测试及 Release 交付打包并未因此视为通过。

## 原生构建和测试

在项目根目录执行：

```sh
python3 scripts/generate_luts.py
cmake -S . -B build/native -DCMAKE_BUILD_TYPE=Release
cmake --build build/native --parallel 8
ctest --test-dir build/native --output-on-failure
```

详细测试场景可以直接运行：

```sh
build/native/photo_core_tests
```

内存检查：

```sh
cmake -S . -B build/asan -DCMAKE_BUILD_TYPE=Debug -DPE_SANITIZE=ON
cmake --build build/asan --parallel 8
ctest --test-dir build/asan --output-on-failure
```

真实样张需自备，并确认有权使用。在 samples/private 下存放本地文件，参考 samples/manifest.example.json 建立实际清单，然后运行：

```sh
python3 scripts/validate_samples.py samples/private/manifest.json --report build/sample-report.json
```

该命令检查全分辨率解码/导出及期望尺寸，并记录耗时，不自动代表画质/色彩的人工验收，也不会上传样张。

## Flutter 检查

安装 Flutter 3.27.4 后，在项目根目录执行：

```sh
sh scripts/bootstrap_app.sh
cd app
dart format --output=none --set-exit-if-changed lib test
flutter analyze
PHOTO_CORE_LIBRARY="$(pwd)/../build/native/libphoto_core.dylib" flutter test
```

首次代码格式检查可能报告待格式化内容，可先运行 dart format lib test，再重新检查。FFI 测试不设置内核路径时会明确跳过，不会用跳过冒充 ABI 验证成功。

## 应用运行和打包

开发运行：

```sh
sh scripts/dev_macos.sh
```

如果出现 Flutter 前台激活失败且没有窗口，应先退出当前调试会话，再重新运行开发脚本。macOS 宿主的 Swift 修改需要完整重启构建，不能仅热重载。开发脚本支持向 Flutter 透传选项；需要详细诊断日志时运行：

```sh
sh scripts/dev_macos.sh --verbose
```

应区分“窗口未置前”与“进程已退出”：若窗口显示且调试连接正常，前台激活提示不阻塞调试；若进程退出，继续依据退出错误和 macOS 崩溃报告定位，不把激活处理当作崩溃修复。

本地 Release 构建并启动独立应用：

```sh
sh scripts/build_macos.sh --open
```

要先执行原生及 Flutter 检查，再打包：

```sh
sh scripts/build_macos.sh --verify --open
```

交付产物应为 dist/光屿.app 和 dist/光屿-macOS.zip；仍须在独立机器验证后再考虑分发。该次打包脚本修改尚未执行，不能把已有 Debug 启动日志当作 Release 验收。
