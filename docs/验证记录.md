## 2026-10-21 RAW 预览预算修正（待用户构建复测）

用户反馈 RAW 估算需 2240MiB、当前预算 2176MiB。定位到预览虽已设置 half_size，检查仍统一使用传感器像素 ×64；这不是实测内存峰值。

本次改为常见整数单平面 Bayer／X-Trans 半尺寸预览的阶段估算：解包阶段按传感器像素 ×16 +64MiB，处理阶段按传感器像素 ×4 +半尺寸像素 ×32 +64MiB，输出阶段按传感器像素 ×4 +半尺寸像素 ×16 +64MiB，取最大值。奇数尺寸向上取整。自分配解码器、浮点/多通道、特殊旋转/像素比例等未确认路径继续采用完整图像的保守估算；解包后检查实际缓冲类型，再决定能否沿用半尺寸预算。预算仍是估计，不能保证第三方库实际峰值。

同时移除 RAW 文件的整份压缩数据预读，保留输入文件大小检查；根据有限 ftyp 文件头识别 HEIF/CR3。用 LibRaw copy_mem_image 的可指定行步幅输出替代 dcraw_make_mem_image，再从右向左原地扩展 RGB→RGBA，保留 LibRaw 的方向/色彩处理，减少整幅 RGB16 副本。LibRaw 自身的 RAW 分配上限也受当前设备预算约束。通用内存不足提示不再建议 RAW 用户直接选择 JPEG 分条导出。

新增待运行回归：常见 RAW 半尺寸估算仍包含传感器开销、大传感器仍超预算、奇数尺寸向上取整、RGB/RGBG 行原地扩展的重叠及边界保护。本轮未运行编译/测试，未收到这张 RAW 的文件路径，不能声称已对该机型复测通过。全尺寸 RAW 导出仍使用完整解码及管线预算，不承诺此次修改能让它在同一预算下通过。

用户命令：完整退出旧应用后执行 `sh scripts/build_macos.sh --verify --open`，或仅重新打包 `sh scripts/build_macos.sh --open`。请复测 RAW 导入的方向、色彩、拍摄信息、滤镜预览，并单独检查原尺寸导出。

## 2026-10-21 HEIF 网格分块编码（待用户构建复测）

用户复测确认 JPEG 11648×8736→HEIF，在带相框的整图编码检查中预计 3786MiB，预算 2297MiB。上一轮移除整图编辑副本没有解决编码峰值，本轮补齐 grid 编码，未提高内存上限。

超过 1024px 的 HEIF 输出逐个编码统一 1024×1024 图块；只保留宽×1024 的 RGB8 行带及当前图块，右侧/底部不足处重复边缘像素，主 grid 记录精确输出尺寸。主图指定为 primary，写入 sRGB NCLX 颜色属性、白名单 EXIF；条带合成白底、调色及相框逻辑保留。压缩图块由 libheif 暂存至写出，因此预算仍包含输出像素×8、带宽×1024×4、单块编码工作区与固定余量；不是恒定内存，也不是实测 RSS。默认 HEIF 依赖最低版本调整至 1.19.7，与已有移动依赖固定版本一致。

## 原生构建和测试

在项目根目录执行：

```sh
python3 scripts/generate_luts.py
cmake -S . -B build/native -DCMAKE_BUILD_TYPE=Release
cmake --build build/native --parallel 8
ctest --test-dir build/native --output-on-failure
```

```sh

```

```sh
cmake -S . -B build/asan -DCMAKE_BUILD_TYPE=Debug -DPE_SANITIZE=ON
cmake --build build/asan --parallel 8
ctest --test-dir build/asan --output-on-failure
```
