## 2. 总体架构

**Flutter 单代码库 + 共享 C/C++ 图像内核**。设计核心：内核厚而纯（纯像素运算、无状态、窄接口），Dart 层管数据与交互，平台胶水层薄到只剩文件与显存。

```
┌──────────────────────────────────────────────────────┐
│  Flutter / Dart 层（四端共享，薄）                     │
│  · 页面与交互：相册、编辑页、滑杆、预设选择器             │
│  · 状态管理：当前参数集、编辑历史（撤销/重做）             │
│  · 预设管理：LUT/参数预设的存储、导入导出、命名           │
│  · 预览调度：小图实时调参、导出时全分辨率重跑管线          │
├──────────────────────────────────────────────────────┤
│  平台胶水层（每端一份，极薄）                            │
│  · macOS / iOS / Android: FFI 直调                     │
│  · HarmonyOS: NAPI 封装                                │
│  · 只做：文件访问权限、相册读写、位图显存传递              │
├──────────────────────────────────────────────────────┤
│  C++ 图像内核（四端共享同一份代码，功能主体）             │
│  ┌────────────────────────────────────────────────┐  │
│  │ 解码模块（格式无关，输出统一 16bit 位图 + 元信息）   │  │
│  │   RAW: LibRaw ｜ JPEG: libjpeg-turbo ｜           │  │
│  │   PNG: libpng ｜ HEIC: libheif ｜ WebP: libwebp   │  │
│  ├────────────────────────────────────────────────┤  │
│  │ RAW 管线：去马赛克 → 白平衡 → 色彩空间转换          │  │
│  │          → 16bit 线性位图                          │  │
│  ├────────────────────────────────────────────────┤  │
│  │ 色彩管理：ICC 统一转 sRGB（lcms2）                  │  │
│  │          JPEG 8bit 上采样至 16bit 内部表示          │  │
│  ├────────────────────────────────────────────────┤  │
│  │ 调色引擎：曝光/对比/高光/阴影/白色/黑色/色温/色调/   │  │
│  │   饱和度/自然饱和度 → 3D LUT 应用                  │  │
│  ├────────────────────────────────────────────────┤  │
│  │ 合成模块：边框绘制、EXIF 文字排版渲染               │  │
│  ├────────────────────────────────────────────────┤  │
│  │ 导出模块：JPEG/PNG/HEIF 编码、EXIF 回写（exiv2）    │  │
│  └────────────────────────────────────────────────┘  │
│  对外窄接口（C ABI，约 5 个函数）：                      │
│    decode(path, options) → Bitmap + Meta              │
│    apply_params(bitmap, params) → Bitmap              │
│    apply_lut(bitmap, lut) → Bitmap                    │
│    add_border(bitmap, spec) → Bitmap                  │
│    encode(bitmap, format, quality) → file             │
└──────────────────────────────────────────────────────┘
```

### 2.1 关键设计原则

1. **功能集中在 C++ 层**：四端像素级一致的结果；性能（16bit 逐像素运算是 C++ 主场）；鸿蒙风险隔离；AI 编码语料最丰富。
2. **内核无状态**：每次调用都是"位图 + 参数 → 新位图"。编辑状态、撤销栈、参数集（JSON 描述）放 Dart 层。好测试、好并行、好移植。
3. **不进内核的三样东西**：编辑状态/历史（Dart）、预设文件管理（Dart）、预览缩略图调度策略（Dart）。
4. **窄接口**：FFI 与 NAPI 都易绑定；内核可脱离手机平台在 macOS 上独立完成单元测试与画质验证。
5. **图像内核平台无关**：不碰任何平台 API，鸿蒙端只是"再加一个编译 target"。
6. **Flutter 版本以 ohos 分支为锚**（如 3.27.x 系列），iOS/Android/macOS 跟随对齐。

## 3. RAW 格式识别策略

### 3.1 格式本质

主流相机 RAW 绝大多数底层是 TIFF 容器（魔数 `II*\0` / `MM\0`），厂商塞私有标签；例外：

- **CR3**（佳能新机型）：ISO BMFF 容器（类似 MP4，ftyp box）
- **RAF**（富士）：自定义容器 + X-Trans 传感器需特殊去马赛克
- **DNG**：TIFF 的标准化超集，iPhone ProRAW / 安卓 RAW 输出均为 DNG（LibRaw 支持最完善）

### 3.2 三层递进识别

```
第 1 层：魔数 / 文件签名（自研，约几十行）
  · II*\0 / MM\0        → TIFF 系候选（ARW/NEF/RW2/ORF/CR2/DNG）
  · "FUJIFILMCCD-RAW"   → RAF
  · ftyp box (ISO BMFF) → CR3 / HEIC 候选，再看 brand
  · FFD8                → JPEG（走普通解码）
  用途：文件选择器过滤、快速分类、UI 标识

第 2 层：TIFF 标签判别（区分同为 TIFF 系的格式）
  · Make 字段：SONY / NIKON / Panasonic / FUJIFILM...
  · DNGVersion 标签存在 → DNG

第 3 层：LibRaw 权威判定
  libraw_open_file() 完成全部识别 + 具体机型匹配
  （内置 1000+ 机型参数表：传感器、黑电平、白平衡系数、色彩矩阵）
  失败则优雅降级提示"不支持此格式"
```

**原则：自研只做第 1 层；不信任扩展名，识别必须看内容。**

### 3.3 已知风险与对策

| 风险 | 对策 |
|---|---|
| 新机型滞后（LibRaw 逆向驱动，新机型需数月跟进） | LibRaw 做成可升级独立模块；维护"已验证机型清单"并在 UI 明示 |
| 富士 X-Trans 去马赛克慢 | 移动端留意性能，纳入基准测试 |
| 高像素 RAW 内存爆炸（6000 万像素 16bit ≈ 700MB） | 预留分块 / 降采样解码策略 |
| 有损压缩 RAW（Sony/尼康部分机型） | LibRaw 可解，纳入样张测试集 |

## 4. JPEG / 普通格式管线

- 输入分流在魔数识别时决定：RAW 走 LibRaw 完整管线；JPEG 走 libjpeg-turbo，跳过 RAW 管线直接进调色引擎。
- **统一 16bit 内部表示**：JPEG 8bit 解码后立即上采样，避免激进调色出现 banding；导出时降回 8bit。
- **EXIF 处理**：解码时提取（喂边框功能）；导出时用 exiv2 原样回写，**永远不改写原文件**。
- **色彩空间**：内嵌 ICC（sRGB / Adobe RGB）经 lcms2 统一转 sRGB 再进调色引擎。
- 导出 JPEG 质量参数开放给用户，默认 95。
- HEIC/HEIF（iPhone 默认格式）、PNG、WebP 顺手支持，解码库四端均有成熟移植。
